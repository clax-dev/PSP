2 · CREAR Y ARRANCAR · H01

El encargo, el camarero y «¡empieza!»

📝Runnable = el ENCARGOqué hay que hacer, escrito en run()
🧑‍🍳Thread = el CAMAREROnew Thread(encargo)
📣start() = «¡EMPIEZA!»arranca un hilo nuevo, una sola vez

La trampa: start() frente a run()

class Camarero implements Runnable {   // el encargo
    public void run() { ... }
}
Thread t = new Thread(new Camarero(1));
t.start();                        // ✅
start() una sola vez → la 2.ª lanza IllegalThreadStateException.

Mejor implements Runnable que extends Thread: solo se puede heredar de una clase.

4 · JOIN, SLEEP E INTERRUPT · H02

Espero a que acabes · siesta · una nota

join(): espero a que acabesSin join, el main hace la caja antes de que terminen.
H02: «no he esperado, ¿el hilo sigue vivo? true»
sleep(ms): siestaDuerme al hilo que ejecuta esa línea. Sirve para simular que algo tarda.
interrupt(): una nota 📝No lo echa: le pide que pare. Él mira isInterrupted() y sale limpio.
H02: «me han interrumpido, salgo limpiamente»
Esquema de siempre: preparar lo compartido → crear → start() a TODOS → join() a TODOS → resultado. Nunca start+join en el mismo bucle.

5 · CONDICIÓN DE CARRERA Y SYNCHRONIZED · H03

Se pisan… y el candado lo arregla

Regla 1 del candado: tiene que ser EL MISMO para todos

private static final Object LOCK = new Object();
synchronized (LOCK) {
    caja++;          // sección crítica: de uno en uno
}                    // se suelta SOLO al salir
Regla 2: solo lo imprescindible dentro. Dentro van de uno en uno: si metes todo el run(), es como tener un solo camarero.

6 · COLECCIONES Y «COMPROBAR Y LUEGO ACTUAR» · H04 · Cafeteria

Pregunta y coge en un solo paso

Cola segura (ConcurrentLinkedQueue) con 1 cliente dentro y 2 camareros. Cada operación es segura… pero dos seguidas no.

// ❌ dos operaciones → hueco
while (!cola.isEmpty()) {
    String c = cola.poll();      // puede ser null
}

// ✅ una sola operación
String c;
while ((c = cola.poll()) != null) {
    atender(c);
}
NormalSegura para hilos
LinkedList (Queue)ConcurrentLinkedQueue
HashMapConcurrentHashMap
ArrayListCopyOnWriteArrayList
H04: ArrayList con varios hilos: esperado 2000 → 1984. CopyOnWriteArrayList: 2000 ✅
Esta trampa vuelve en el tema 3: entre soltar el readLock y coger el writeLock hay un hueco → hay que volver a comprobar.
